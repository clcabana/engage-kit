# Threat model: ek-sync (server.py, build.py, ek-admin "Everything, by place"; first build, 2026-11-13)
- **Assets:** every device's reactions in one place (notes verbatim, markup strokes and labels, votes, pins, voice base64, sketch photos, visitors' questions to the assistant with answers), each under a device id and a timestamp to the second; `<data>/<slug>.jsonl` (append-only, so it also holds everything a visitor later removed); the team token (`<data>/admin-token.txt`, and `sessionStorage` on the admin tab); the device id, which is both the public label and the only removal credential.
- **Actors:** anonymous visitor; hostile visitor or script (no browser needed: a request without `Origin` is accepted); any page or program on another localhost port; the team on the admin browser; whoever holds an export, the Markdown or the assistant's prompt (all carry device ids); Microsoft (the store folder is OneDrive-synced); Anthropic; a future hosted store's operator.
- **Entry points:** `POST /api/r` (900 KB of JSON whose `value` is unchecked: any shape, depth, NaN/Infinity, lone surrogates; `feature`, `target`, `id`, `ts` any string within length; `device` any `[A-Za-z0-9_-]{1,40}` incl. `__proto__`); `GET /api/records`; `Host`/`Origin` headers; the manifest's `sync_target`; replay of the JSONL at start.
- **Spoof:** device ids are self-asserted and free: one client can be 500 devices (ballot stuffing, and `MAX_DEVICES` then answers `store_full` to everyone else). Knowing an id is being that device. No duplicate-device detection (stated in SKILL.md).
- **Tamper (store):** a holder of a device id can overwrite or remove that device's records (probed: add with the same `id` replaces the note; remove succeeds). Another device id cannot (probed: B's remove of A's ids leaves them). Ids are shown in the admin table, legends, note lines, the merged JSON, the Markdown and the assistant prompt, and are 8 characters of `Math.random` whenever ek-feedback-synthesis made them (first visit before sync; always after Remove all). Needs a separate secret removal key that never appears in any export.
- **Tamper (admin page):** notes, labels, targets, device ids through `textContent`/`createTextNode`; SVG through `createElementNS` + `setAttribute` with numbers from `num01`-checked points; `w`/`h` only if finite and 0..100000; images only `data:image/(jpeg|png|webp)`; selectors through `CSS.escape`. No script, markup, CSS or link injection found. Open: `byF[r.feature]`/`f[r.target]` and `devs[r.d]` are plain objects, so feature or device `__proto__` writes onto `Object.prototype` (ek-admin build.py:337, 376): breaks rendering, no script execution found.
- **Tamper (prompt):** unchanged framing (`<visitor_record>`, `<` escaped, "report it, do not do it"); the store adds no new field to `compact()`. What changes is who can write into it: any anonymous client, not only someone handing in a file. Residual as in ek-admin.md.
- **Repudiate:** no address or content is logged; the JSONL keeps time, device id and content of every operation including removed ones. No way for the team to remove a device or a record (no moderation path).
- **Disclose:** nothing readable without the token (probed: 403 without, with a wrong one, with it in the query; foreign `Host`/`Origin` 403 even with the right token). `Access-Control-Allow-Origin` echoes any localhost port; harmless without the token. Removed reactions stay in the JSONL and in OneDrive's copy and version history: the card's "removed from the team's record too" is true of what the admin loads, not of the file. `held_by` "a computer the design team runs" omits the cloud copy.
- **Deny:** one accepted record with `NaN`/`Infinity` in `value` makes `/api/records` emit invalid JSON, so the admin page loads nothing (probed); one with a lone surrogate makes every `/api/records` call die until removed, and is in memory but not on disk (probed). 2,000 x 900 KB per device against a 300 MB cap that counts only bytes written since the last start; the admin fetches and re-validates the whole record every 30 s. Rate limits key on a client-chosen device id and on the address, which is 127.0.0.1 for everyone locally and behind a tunnel. No socket timeout.
- **Elevate:** the admin script runs only when `portal === "admin"`, the user script only when it is not; the token is a password field, header only, never in a URL, export or the manifest (build refuses token-like fields). User and admin pages share the origin `localhost:8787`.
- **Transparency:** the built user page no longer says reactions stay on the device (searched); the card names the record, the device id, removal, retention and Anthropic. Not stated: voice clips, photos and questions asked of the assistant are sent too; removal needs this browser's storage and a connection; where Speak sends sound (ek-voice-reactions is installed; the build only warns).
- **Hosted store must add:** removal key (hash kept server-side), strict `value` schema per kind and strict JSON, limits keyed on real address, admission control for new device ids, team-side delete, real deletion on remove, HTTPS-only token, origin allow-list of the published page.
