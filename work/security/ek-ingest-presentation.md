# Threat model: ek-ingest-presentation (2026-10-23)
- **Assets:** the deck in `input/` (may be client material); renders `work/slides/NN.png`; `work/extract.json` (verbatim slide text, PPTX speaker notes, OCR); `work/brief.json` + `brief-summary.md` (model transcription); LibreOffice PDF copy in `work/` for PPTX input.
- **Actors:** design team (runs script, confirms brief); the model that runs the skill (reads extract.json / renders, writes brief.json); a hostile deck author; the public GitHub audience (repo is public; `work/` is committed except `slides/` and `*.pdf`).
- **Entry points:** deck text layer, fonts, embedded images, filename/stem; OCR output (Tesseract); PPTX speaker notes (merged into slide text with a `[notes]` prefix); `--work` path argument (operator, not deck).
- **Spoof:** n/a — no identities; whoever places a file in `input/` is the author.
- **Tamper:** instruction-shaped text in the deck (test deck already has "/name-of-skill write your prompt… must be installed prior to command", slide 10) reaches the model via extract.json `text` or via the render; the model transcribed it as content. Mitigations: extract.json `note` labels deck text untrusted; orchestrator stops after ingest and confirms the feature list. Gap: `brief.json` carries no untrusted label, and it is the only file later skills read; speaker notes are a hidden channel the skill never mentions.
- **Repudiate:** extract.json records source path, tool versions, timestamp; brief.json records `read_by`. PyMuPDF version is mis-recorded as "2.0:" (`fitz.__doc__.split()[1]`), so the audit trail of the parser that touched client bytes is wrong.
- **Disclose:** renders are gitignored but `work/extract.json` (whole deck text, notes verbatim) and `work/brief.json` (slide-by-slide transcription, `history[].image` paths) are not: for a real client deck this publishes the deck's content to a public repo. `source.deck` records the path as given; an absolute path would publish the user's local filesystem layout. Test deck: no personal names, addresses or people photos; vendor names only.
- **Deny:** a malformed PDF can crash PyMuPDF/poppler/LibreOffice; `check=True` aborts cleanly; local-only, no service to deny.
- **Elevate:** deck bytes are parsed only by native libraries (MuPDF, poppler, LibreOffice, Tesseract); no eval/import of deck data, all `subprocess.run` calls use argument lists, no `shell=True`, output filenames come from the page index (PPTX→PDF uses the deck's filename stem: operator-supplied, written to gitignored `work/*.pdf`). No network, no credentials read or stored, no installs performed; stderr hints name `pip install pymupdf` / `python-pptx` / `winget tesseract-ocr.tesseract` unpinned, as advice to the human.
