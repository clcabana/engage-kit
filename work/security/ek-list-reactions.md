# Threat model: ek-list-reactions (2026-11-04)
- **Assets:** principle/program names (≤80 chars), `text`/`use` (≤600), `note` (≤200), `source_slide`, `contested` from the deck, in markup only (the inline `LS` JSON carries group ids, fixed titles and counts, no brief text); visitor notes, voice clips and ranks (`kind:'vote'`, value 1-5) per item name in the shell's `localStorage['ek:'+slug]`; the ranking the client later sees summed in synthesis.
- **Actors:** anonymous visitor on their own or a shared phone (real project: 19 people, own phones); hostile visitor (devtools, planted store, 500 taps); hostile deck author / ingest model (controls every brief string, including a `text` that literally says "[wording to confirm]"); design team running `build.py` with `--groups`; later features that read `ek:context`.
- **Entry points:** `brief.principles[]`, `brief.program[]` → `groups_from_brief()` (build.py:56-87) → `section_html()` (90-139); `--groups` (operator; split on commas, every token checked against `GROUPS`, 274-277); `EK.reactions()` → `rankOf()`/`render()` (186, 207-218); the shell bar (notes/voice, target = whatever `EK.context` last set); no `location.hash`, no imported file, no network.
- **Spoof:** the two placeholders ("[wording to confirm]", "What this is for is not described in the presentation.") sit in the same `<p>` as deck text and are followed by "From the presentation, slide N" (build.py:111-112). Sighted visitors get a dashed card and italic muted type; a screen reader hears the placeholder attributed to the presentation. A brief whose `text` is literally "[wording to confirm]" has `tbc=False` and loses even the visual mark.
- **Tamper:** every brief string that reaches markup is `html.escape`d inside quoted attributes (`data-target`, `data-slide`, both `aria-label`s, the `<ol>` label) or text (`.ls-name`, `<p>`, `.ls-note`, slide line); element ids are `gid` ∈ `GROUPS` + index, never brief text. The script uses `textContent`/`createElement`/`createTextNode`/`setAttribute` only: no `innerHTML`, `eval`, `Function` or `on*=`. `rankOf` accepts only integers 1..5 (not ≤ list length: a planted `5` on a 3-item list shows "#5", harmless); the last vote per target wins. Voice records need `audio/` MIME and base64 alphabet before a `data:` `src` is built. `data-slide` is escaped twice (`7&8` → `7&amp;8` in the bar); `--groups principles,principles` duplicates DOM ids (operator-only).
- **Repudiate:** each item prints its slide or "slide not recorded". A note typed while no item is open (context target = list title, or "ranking: …" while the rank box is open) is stored, counted in the nav and exported, but never rendered in the section: the visitor cannot see it or remove it singly.
- **Disclose:** nothing personal collected; records carry shell `id`+`ts` only; `ek:context` passes item names to trusted feature code. The bar chip shows the name via `textContent`; an unbroken name over ~40 chars is clipped inside the chip (`.chip` is inline-flex with no `overflow-wrap`); nothing escapes the viewport.
- **Deny:** Save (build.py:227) removes every old vote for the list, then calls `EK.react` per pick; on a full store `react` returns null, the toast is honest, but the old ranking is already gone and a partial new one can remain (no rollback). Render is O(items × reactions) per event; 12 items × 600 chars bounds the markup.
- **Elevate:** `build.py` reads `--brief` and `--out`, writes `--out`; stdlib only; no subprocess, network, env or credentials; nothing read is executed.
