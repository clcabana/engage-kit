# Threat model: ek-publish (publish.py, chain.py --portal; 2026-11-13)
- **Assets:** passphrase files (`user.txt`, `admin.txt`), the plain builds in `output/` (unencrypted tool incl. photos), the locked pages, the project README (local and public copy), the manifest (rewritten), the person's `gh` credentials.
- **Actors:** the person; an agent running the script; GitHub (public repo, Pages, history forever); anyone reading the public repo; OneDrive (syncs the kit folder, `projects/` included).
- **Entry points:** manifest `publish`/`chat`/`hosting`/`data` blocks (model-filled), `--brief`, `--out-dir`, `--run-gh`.
- **Argument construction:** every subprocess is an argv list, no shell; `repo` regex-checked (44), portal paths hex (42); lock titles capped. `pages_dir` is unchecked: `"../x"` or an absolute path writes pages and README outside the repo (224-225). Fix: `^[A-Za-z0-9_-]{1,40}$`.
- **Disclose (public README, BLOCKING):** `<pages_dir>/README.md` (322) is written with `# {project.name}` (98) and `kv_lines(hosting)+kv_lines(data)` verbatim (167), plus chat mode/model and both links labelled "Admin portal". On the real manifest that publishes the client's name, the group size, the passphrase file path and the collection/retention notes on a public repo that Pages may render at the site root. Fix: public copy titled with `user_portal.title`, no hosting/data/chat blocks, no portal labels; or write no public copy unless `publish.public_readme: true`.
- **Agency (BLOCKING, checklist 6):** `--run-gh` uses the person's gh token to create a **public** repo and enable Pages with no prompt (329-343); an agent can pass the flag. Fix: refuse `--run-gh` when `not sys.stdin.isatty()`, and require typing the repo name to confirm.
- **Passphrase files:** generated by lock.py, chmod 600 on POSIX only; on Windows they inherit the user-profile ACL and OneDrive uploads them to Microsoft's cloud. A relative `passphrases_dir` resolves against the manifest's folder (233): the real value `projects/qop-masterplan/work` becomes `projects/qop-masterplan/projects/qop-masterplan/work`, so the existing `user.txt` is not found and a new user passphrase would be generated silently on the next run. Fix the value to `work`; print "generated" loudly when a file is new.
- **Gate:** both gates read the same `hosting.lock_key`; "remember" is off (shared origin): correct. Re-lock keeps old ciphertext in git history.
- **Temp manifest:** `.ek-admin-manifest-*.json` next to the real manifest, removed in `finally` (chain.py:100-104); left only on a hard kill; same content as the manifest, under gitignored `projects/`. OK.
- **BOM:** stripped by rewriting the manifest (194-197) with `json.dumps`: content-preserving, loses key order/formatting only. OK.
- **Tamper / repudiate:** n/a; nothing commits or pushes. The script never reads or prints a passphrase (lock.py prints the file path and length only).
- **Origin:** github-pages for an owner's project repo is `<owner>.github.io`, shared by every repo of that owner; both portals share it with each other in any case.
