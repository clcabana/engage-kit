# Threat model: ek-timeline (2026-10-25)
- **Assets:** history text, years and slide numbers from the deck (markup + inline `TL` JSON); deck images as `data:` URIs in `<img>`; visitor memories (`feature:'timeline'`, target = year or `undated: <first five words>`, notes now, voice clips as base64 later) in the shell's `localStorage['ek:'+slug]`; any image file on the design team's machine that `--root`/`history[].image` can reach.
- **Actors:** anonymous visitor on a shared table phone; hostile visitor (devtools, planted localStorage); hostile deck author (controls text, years, `source_slide`, image files and, via the ingest model, `history[].image` paths); design team running `build.py`; the model generating later features that read `brief.json` or reuse these SVGs.
- **Entry points:** `brief.history[]` → `events_from_brief()` → `section_html()` markup and `TL` JSON; image bytes on disk (SVG/PNG/JPEG/WebP/GIF, Pillow decode for rasters >200 KB) → `embed_image()`; `EK.reactions()` → `render()`; `location.hash` (shell only; the feature reads none of it); `--root`, `--brief`, `--out` (operator).
- **Spoof:** n/a — no identities; a memory is one anonymous voice; the deck's claims are labelled "From the presentation, slide N".
- **Tamper:** every brief string that reaches markup is `html.escape`d inside quoted attributes or text (`data-target`, both `aria-label`s, `.tl-year`, `<p>`, slide, rail, "Also in the record"); `src` is a build-made `data:` URI (allowlisted MIME, base64 alphabet). `TL` is `json_inline`d but carries `targets[]` (brief text) that the script never reads. `render()` is `textContent`/`createElement` only; no `innerHTML`, `eval`, `Function` or `on*=` anywhere in the block. Voice: `src` always starts `data:` and MIME must match `/^audio\//`, so a tampered record can at worst give a broken player; the regex accepts `audio/x;base64,...` and newlines (robustness, not execution).
- **Repudiate:** each scene names its slide; events without `source_slide` print "From the presentation" with no number and the "Also in the record" list prints none, both silently. Memories carry the shell's `id`+`ts` only (no device id).
- **Disclose:** `embed_image(root / img)` (build.py:91, 43-54) never checks containment: an absolute path, `..\..\`, or on Windows a UNC path in `history[].image` embeds any file with an image extension from the team's machine or a sibling client folder into the public page (`is_file()` on `\\host\share` also makes an SMB connection). Raster bytes ≤200 KB (and all bytes when Pillow is absent) are embedded verbatim, EXIF/GPS included. Archival photos may show identifiable residents or children. Memories tied to a year plus a voice clip can identify an older resident; previous visitors' clips and notes render under the caption for the next person on a shared phone (shell card covers this).
- **Deny:** Pillow errors other than `ImportError` (corrupt file, decompression bomb) are uncaught at build.py:62-72 and abort the build; a multi-MB `base64` string in one tampered record is rebuilt into a `data:` URI on every `render()` (local only). Twelve 1400 px JPEGs ≈ 3-4 MB of page on public Wi-Fi: warned at 1.5 MB, not blocked.
- **Elevate:** `build.py` reads `--brief`, `--out`, image files, imports Pillow if present; writes `--out` only; no subprocess, network, env or credentials (except the UNC case above). SVGs are shown through `<img>`, so script, event handlers, external `href`/`url()`, `<foreignObject>` and entity tricks cannot run; the pre-check at build.py:58 misses `href=javascript:`, unquoted `href=http`, `url(http…)` in `style`, `<!ENTITY`, `<foreignObject>` and `<?xml-stylesheet`, which only matters if a later feature inlines the same SVG via `innerHTML`.
