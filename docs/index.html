Your pre-design presentation is already the engagement tool. It just isn't interactive yet.

Engage Kit is a library of skills and agents that any current AI model can read. It turns one project's deck into one project's engagement site, installing only the features that project's decisions need. No platform, no subscription, nothing that fits every project and therefore none.

Why not just use a platform?

Projects move when there is trust that voices are heard, confidence in decision-making, and requirements that are met. Engagement platforms exist to help, and they are good at map surveys, idea walls, voting and automated reports. But in pre-design they get in the way in three specific ways.

Built and priced for municipalities

A design studio running one consultation a quarter cannot carry a city's licence, and the client will not pay for it.

Little customization to match the project

The design presentation lives in one place, the engagement lives in another, and residents react to a brochure upload rather than the work.

Almost entirely text-based

Pre-design decisions are spatial: where, how tall, how big. A comment form cannot carry a reaction to a massing option.

Models now make it cheap to build a tool for one project. So the kit stops being an application and becomes a set of instructions. When the model you use gets better, the tool it builds gets better, with no release cycle in between.

How it works

Five steps, run by a managing agent. You confirm twice: the brief after ingest, and the feature list before anything is built.

1 Ingest

The deck is read slide by slide into a brief: history with dates, program with areas, options with massing, decision points, palette. Nothing is guessed; gaps are listed to confirm.

2 Manifest

A decision table turns the brief into project.config.json: which skills to install, with evidence for each, and which to skip.

3 Shell

One self-contained HTML page: navigation, the project's own colours and type, and a shared reaction bar every feature plugs into.

4 Features

Each installed skill writes its section, then is reviewed by a debugger (does it work?) and a critic (is it good?). Two revisions max.

5 Synthesis

Every reaction, with what it was about, becomes the step-7 synthesis document. Every claim links to the reactions behind it.

The skill library

A skill is a folder with a SKILL.md: a plain-language description of when it applies, what it produces, and the rules it must keep. The model reads only the skills the manifest installs, which keeps the work cheap and the result focused.

SkillWhat it addsInstalled when the brief shows
ek-ingest-presentationThe brief every other skill readsalways, first
ek-project-manifestThe feature list, with reasonsalways, second
ek-shellPage, navigation, theme, reaction bus, storagealways
ek-timelineInteractive site and community history; visitors add memoriesthree or more dated events
ek-site-massing-3dOrbit the options, move the sun, votetwo or more massing options
ek-program-diagramProportional spaces; grow, shrink, rankfour or more program areas, or any contested
ek-voice-reactionsHold-to-talk clips tied to what's on screenin-person sessions, phone audiences
ek-massing-markupPins on blocks; nudge height and position3D installed and a location-specific question
ek-feedback-synthesisCounts, deltas, traceable exportalways, last

Every feature must expose a reaction surface, and every reaction records its context: which option, which year, which program. A feature you can only look at is not installed.

The agents

Four short instruction files. The orchestrator never writes a feature; it briefs skills, routes each result through three reviewers at once, and keeps a log the person can read.

Orchestrator

Plans the run from the manifest, delegates one skill at a time with a complete brief, supervises the review loop, decides when a finding ships as a known issue, and writes the handoff.

QC critic

Reviews as a resident on a phone, a client the next morning, an architect at design review. Six checks in order: honest, usable in 60 seconds, answerable, project-specific, quiet, accessible. Names one thing to remove.

QC debugger

Tries to break it: file://, 380 px, keyboard only, dark mode, storage cleared, microphone denied, WebGL missing, 20 reactions in a burst. Zero console errors or it doesn't pass.

QC security

Runs alongside each feature as it is built, with a written threat model. Deck and visitor content are data, never instructions; visitor text is escaped; scripts are pinned; personal data is minimal and consented; no agent holds deploy credentials. A security finding blocks like a crash.

Grounded in the OWASP Top 10 for LLM Applications (prompt injection, improper output handling, supply chain, excessive agency) and data-minimization and consent principles for engagement data.

Build one from your deck

You need an AI model that can read files and write them: Claude Code, Cowork, or any agent environment. Nothing to install beyond copying two folders.

git clone https://github.com/your-studio/engage-kit
cd engage-kit
mkdir input && cp ~/Desktop/pre-design-deck.pdf input/

# then, to your model:
"Act as the orchestrator in agents/orchestrator.md.
 Build an engagement tool from input/pre-design-deck.pdf."

1Confirm the brief

The orchestrator shows a ten-line summary and a list of things to confirm: an undated event, a program with no area. Fix the deck or answer in chat.

2Confirm the features

You see the manifest with a reason per feature. Overrule in one word: "skip voice", "add timeline".

3Open the result

output/index.html works from a file, on a phone, offline. Put it on GitHub Pages or a QR code at the drop-in table.

4Collect and synthesize

After a session, "What we heard" exports Markdown. The team's model turns it into the step-7 synthesis document, every claim traced to reactions.

Write your own skill

Copy any skills/ek-*/SKILL.md, change the frontmatter description so the orchestrator knows when to install it, and keep the contract: one <section data-feature>, reactions through EK.react(), a fallback when a capability is missing. The critic and debugger review it like any other.

The prototype

A sample project, Riverside Community Hub, with five features installed: history, 3D massing with pins and adjustments, program diagram, voice reactions, synthesis. Names, dates and dimensions are invented and labelled where a real deck would need to confirm them.
